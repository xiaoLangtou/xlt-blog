# 远端附件位置变更保护

此次修复在保存存储配置前，将解密后的当前远端配置与合并后的新配置比较，并把对象位置限定为 endpoint 与 bucket。`rusfs` 或 `s3` 的位置发生变化时，服务只在该后端确实仍有关联附件时拒绝保存，避免同类型后端切换到另一对象位置而遗弃旧对象。凭据、region、pathStyle 与 publicUrlBase 不参与位置判定，成功保存仍沿用原有加密、落库与驱动缓存失效顺序。**Watch for:** 未发现待修复的行为或凭据暴露风险（confirmed）。

**Verdict**: APPROVED

## High-level view

保存流程对 `rusfs` 和 `s3` 分别判定 endpoint 或 bucket 是否改变；只有位置改变且 `attachments.storage` 归属相同后端时才中止，因此不会把无关后端或非位置配置更新误判为迁移。

拒绝路径只返回固定的迁移提示。允许的更新仍按原流程加密写入、刷新 ORM 并清空驱动缓存，凭据不会进入异常消息或响应。

## 同类型远端存储的位置切换受附件归属保护

`saveConfig` 在加密和写入 `Setting` 之前调用 `assertRemoteStorageLocationsCanChange(current, config)`。该检查逐一比较 `rusfs` 与 `s3` 的规范化 endpoint 以及经过去空白处理的 bucket；URL endpoint 由 `URL` 规范化并移除末尾斜杠，避免单纯格式差异触发拒绝。实际位置变化时，查询条件限定为 `Attachment.storage === backend`，因此只有仍归属该后端的附件会阻止更新；拒绝时不会写入新配置或清理已有驱动缓存（confirmed）。

## 非位置配置更新与凭据边界

位置判定只读取 endpoint 和 bucket，未读取 accessKey、secretKey、region、pathStyle 或 publicUrlBase；这些字段的单独变更不会因已有附件而被拒绝（confirmed）。当前配置在比较前解密以保持 masked credential 回填的既有语义，但拒绝消息为固定文本，返回值继续由 `toMaskedConfig` 生成，因此新增路径不会把 access key 或 secret key 暴露给调用方（confirmed）。

## 保存后驱动实例仍与配置同步

通过位置保护后，服务仍依次加密远端凭据、`flush`，再清空 `drivers` 缓存。允许的凭据、region、pathStyle 或 publicUrlBase 更新会在下一次驱动获取时使用新配置；被拒绝的位置更新不会造成缓存与持久化配置分离（confirmed）。

未发现 `StorageService` 的专项测试文件，未能以自动化用例直接覆盖有/无附件、同位置格式化差异和非位置字段变更；本次结论基于代码路径审查与服务构建（confirmed）。
