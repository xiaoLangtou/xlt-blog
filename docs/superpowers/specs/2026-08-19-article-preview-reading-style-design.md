# 精致文章阅读样式设计

**日期：** 2026-08-19  
**状态：** 已完成视觉方向确认，待用户审阅本文档后进入实施计划

## 目标

将已确认的「紧凑书籍装帧 + 技术文档」阅读样式，应用到：

1. 后台 `editor.vue` 中的文章预览抽屉；
2. 前台 `posts/[slug].vue` 的真实文章页。

文章在两端应保持同一阅读节奏和内容元素表现，同时继续服从各自应用已存在的亮色 / 暗色主题机制。渲染管线、编辑器切换、保存、发布、代码主题选择和 SSR 均不改变。

## 已确认的视觉语言

- **基调：** 黛蓝作为层级与标题色，朱砂只用于关键强调（章节引导线、分隔符、结尾印）；纸张底色与细书框承载阅读，而非卡片式后台界面。
- **排版：** 标题使用既有宋体 / serif 字体栈；正文字体保持系统 sans-serif；代码使用等宽字体。
- **节奏：** 技术长文优先紧凑可扫读。正文行高为 `1.78`；段落、列表、代码、表格保持短而清晰的垂直间距；二级标题拥有稳定但不夸张的章节分界。
- **标志元素：** `hr` 以居中的朱砂 `※` 收束；其本身高度为 `14px`，仅保留 `22px` 的上方间距；紧接的 `h2` 顶部间距固定为 `18px`，避免两段外边距相加形成大面积空白。

## 范围与结构

### 前台真实文章

`apps/web/app/pages/posts/[slug].vue` 已具有元信息、宋体标题、摘要、封面、正文和结尾印的书籍装帧结构。实施时：

- 保持其数据获取、SEO、阅读进度和评论结构不变；
- 保持 `article-content editor-${article.editorType}` 容器及后端返回的安全 HTML 不变；
- 在 `apps/web/app/assets/css/main.css` 的 `.article-content` 范围内补齐并收紧正文样式；
- 对标题、段落、列表、链接、行内代码、Shiki `pre`、表格和 `hr` 应用已确认的尺寸与间距；
- 让宽表格横向滚动而不撑破移动端正文列。

### 后台预览抽屉

`apps/art-design-pro/src/views/blog/articles/editor.vue` 现有预览使用全屏 Element Plus Drawer，并经 `/admin/.../preview` 获取与发布相同的渲染 HTML。实施时：

- 保持 `refreshPreview()`、请求参数、竞态 token、加载态和关闭操作不变；
- 将通用 Tailwind `prose` 外观替换为与前台一致的语义化预览壳：刊头 / 返回编辑、文章元信息、标题、摘要、封面、正文和收束印；
- 正文继续使用 `article-content-preview`，增加 `editor-${form.editorType}` 和 `code-theme-${form.codeTheme}`，不改变 HTML 注入来源；
- 复用后台现有的 `article-content.scss` 作为后台预览正文的唯一责任边界，去除 `editor.vue` 中与其重叠的局部 prose 变量，避免样式竞争；
- 保持抽屉在桌面端全屏、在移动端可滚动，且代码与表格横向滚动。

## 主题与代码高亮

两端使用自己的主题状态与变量，而不是添加新的全局主题开关：

- 前台：以现有 `.dark` 和 Nuxt UI `--ui-*` 变量为基础，加入与亮色纸张、墨色、边框、代码背景对应的深色青黑 / 蓝灰变量。
- 后台：以当前 `--default-*`、`--art-gray-*`、`--theme-color` 和主题根状态为基础；不硬编码白底或灰黑文字，避免预览在后台暗色主题下失真。
- Shiki：亮色继承服务端返回的默认高亮；暗色状态下由 `.dark ... .shiki, .dark ... .shiki span` 使用 `--shiki-dark` 与 `--shiki-dark-bg` 覆盖内联颜色和背景。
- Notion 色板、任务列表、`details`、文本对齐等现有富文本兼容规则保留；本次只调整其在文章正文中的视觉归属与主题变量。

## 元素规格

| 元素 | 核心规则 |
| --- | --- |
| 正文 | `16px`、`1.78` 行高；段落上下 `9px` |
| `h2` | serif；朱砂左引导线；下方细规则线；通常上方 `48px`、下方 `17px` |
| `hr + h2` | 标题上方 `18px`，确保章节转场紧凑 |
| `h3` / `h4` | 分别为 `21px` / `17px`；上方 `28px` / `21px` |
| 列表 | 上下 `10px`；列表项 `3px`；marker 朱砂 |
| 行内代码 | 浅红灰底、细边框、等宽字体；暗色改用深红灰底与浅红文字 |
| Shiki 代码块 | 上下 `16px`、内边距 `17px 21px`、左侧黛蓝细线、低圆角、可横向滚动 |
| 表格 | 上下 `18px`、细边框、蓝灰表头、隔行极浅底色；移动端横向滚动 |
| 分隔符 | `14px` 高、仅上方 `22px`，居中 `※`；暗色纸张背景同步 |

## 非目标

- 不修改后端 Markdown / TipTap / Domternal 转换、净化或 Shiki 渲染逻辑。
- 不重写三种编辑器的编辑态样式。
- 不新增字体文件、第三方依赖、主题开关或 API。
- 不修改文章数据结构、路由、SEO、评论或阅读进度计算。

## 验收标准

1. 在后台文章编辑页点击预览，文章以书籍装帧式标题区和紧凑正文呈现；关闭、刷新预览、切换代码主题仍正常。
2. 同一内容在前台文章页与后台预览中，标题层级、正文密度、列表、表格、行内代码、Shiki 代码块和 `hr` 的阅读节奏一致。
3. 分隔符与下一节 `h2` 不出现明显大面积空白；规则值满足 `14px / 22px（仅上方） / 18px`。
4. 前台 `.dark` 与后台暗色主题下，正文、标题、边框、表格、行内代码、Shiki 前景/背景均可辨识，无白色硬编码造成的反差问题。
5. 窄屏下，页面不产生水平溢出；代码块和宽表格单独横向滚动。
6. 后台前端构建与静态检查通过；Nuxt 前台构建通过。

## 验证策略

- 对后台执行目标构建 / lint，确保 Vue 模板与样式可编译。
- 对前台执行目标 Nuxt 构建，确保 SSR 和 CSS 处理正常。
- 使用现有的 Java 长文 HTML，在亮色与暗色主题下手工检查后台预览和前台真实文章，重点检查上述验收元素与窄屏布局。
- 不将与本任务无关的现有 56 项工作区改动纳入本次修改或验证结论。
