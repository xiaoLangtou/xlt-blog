# 文档预览改造方案

## 1. 背景与目标

当前问题：大文件（PDF/Office 文档）预览需等待完整下载才能渲染，体验差。

目标：实现"边下边看、按需加载"的预览体验，不改变原文件的存储与下载逻辑。

## 2. 方案总览

| 文件类型 | 预览方式 |
|---|---|
| PDF | 直接走 HTTP Range 请求 + PDF.js 流式渲染，无需转换 |
| docx / xlsx / pptx / txt 等 | 异步转换为 PDF，缓存后复用同一套 PDF 预览链路 |

原文件与预览文件分离：原文件只负责下载，预览文件是转换/缓存出来的独立产物。

## 3. 整体链路

```
上传 → 原文件落 RustFS（原文件桶）
         │
         ├─ PDF：登记预览记录，status=ready，直接复用原文件 key
         │
         └─ 非 PDF：登记预览记录，status=pending → 推入转换队列（BullMQ + Redis）
                        │
                        ▼
              独立部署的转换 worker（LibreOffice headless）
                        │  拉源文件 → 本地转换 → 传回预览桶
                        ▼
              status=ready，previewKey=转换后 PDF 的 key
```

## 4. 数据模型（MikroORM）

```ts
@Entity()
class DocPreview {
  @PrimaryKey() id: string;
  @Property() sourceKey: string;        // 原文件 key
  @Property() sourceType: string;       // pdf / docx / xlsx / pptx ...
  @Enum(() => PreviewStatus)
  status: PreviewStatus;                // pending / converting / ready / failed
  @Property({ nullable: true }) previewKey?: string;
  @Property({ nullable: true }) pageCount?: number;
  @Property({ nullable: true }) errorMsg?: string;
  @Property() createdAt: Date;
  @Property({ nullable: true }) convertedAt?: Date;
}
```

## 5. 转换队列与 Worker

**触发**：API 侧只登记 job（sourceKey + docId），立即返回，不阻塞上传请求。

**Worker 部署**：独立进程/容器，不与主 API 混部，避免 LibreOffice 占用资源拖慢接口。

**处理步骤**：
1. 消费到 job → 状态改为 `converting`（前端可轮询感知）
2. 拉源文件到本地临时目录
3. `soffice --headless --convert-to pdf` 转换
4. 转换结果上传预览桶，读取页数，清理本地临时文件
5. 成功 → `status=ready`；失败 → 记录 `errorMsg`，`status=failed`

**稳定性兜底**：
- 单任务超时（如 60s），超时即判失败
- 并发数限制（如 2-3 个并行），防止多个大文件同时打满机器
- 区分可重试失败（超时/网络问题，允许重试 ≤2 次）与不可重试失败（文件损坏/格式不支持）
- 大文件（如 >50MB）可跳过自动转换，改为用户手动触发生成

**扩展路径**：先单机 LibreOffice 顶量；量上来后横向扩容 worker 副本，或替换为专用转换服务（如 Gotenberg），接口不变。

## 6. 存储与网络配置

- **原文件桶**：保持现状（私有/签名下载），不受影响
- **预览桶**（独立新建，如 `xlt-blog-preview`）：访问策略设为公有只读，专门存放转换后的 PDF，避免预览链路影响原文件权限模型
- **CORS**：预览桶需暴露 `Accept-Ranges` / `Content-Range` / `Content-Length`，允许 `Range` 请求头
- **反向代理（Nginx）**：`proxy_buffering off`，确保 206 分片响应透传，不被缓冲成整包

## 7. 后端接口

```
POST /api/docs/upload          # 上传原文件，异步触发预览生成
GET  /api/docs/:id/preview     # 返回 { status, previewUrl, pageCount }
```

`pending` / `converting` 状态下前端轮询（或 SSE）获取进度，避免上传后长时间空白等待。

## 8. 前端

封装 `<DocPreviewer :doc-id>` 组件（放入 `packages/shared`，供 Nuxt web 与 Vue admin 共用）：
- `pending`/`converting`：骨架屏 + 进度提示
- `ready`：PDF.js 加载 `previewUrl`（`disableRange: false`），滚动到哪页拉哪页
- `failed`：提示 + 下载按钮兜底

Domternal 编辑器中的文档卡片直接嵌入该组件，编辑态和阅读态复用同一实现。

## 9. 实施优先级

1. PDF 直接预览（Range + PDF.js）—— 成本最低，立即见效
2. BullMQ 转换队列，覆盖 docx/xlsx/pptx
3. 失败兜底与大文件跳过策略
4. 预览文件生命周期清理（原文件删除/覆盖时级联清理对应预览缓存）
